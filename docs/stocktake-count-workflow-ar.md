# شريحة العد في واجهة الجرد الأصلية

## النطاق المرتبط
09.4 و04.1 و04.2 و04.5 و12.2 و14.2 و14.3. لا تغيير للمعرّفات الـ73 أو حالات القبول الـ22. اتفاق إدارة النظام مثبت في `system-administration-agreement-ar.md`؛ تنفيذه يلي إغلاق هذه الشريحة.

## ما تغير
- الواجهة الأصلية `/inventory/stocktake` ترسل كل مسحة كزيادة ذرية للخادم، منفصلة عن تعديل العدد المطلق.
- تحفظ المحاولة قبل الإرسال داخل سجل خاص بالمستخدم والشركة والجرد في المتصفح. إعادة التحميل تعيد المعرف والبيانات نفسيهما. قفل Web Locks بين النوافذ يمنع استبدال محاولة غير محسومة؛ المتصفح غير الداعم لا يرسل المسحة.
- لا نجاح قبل الرد المؤكد. أخطاء البحث/الصلاحية لا تسمى باركودًا مجهولًا. فشل الشبكة و502 يحفظان المحاولة؛ رفض لاحق بعد نتيجة مجهولة لا يمحو دليلها.
- `count_revision` عداد مستقل لكل سطر يمنع التعديل المطلق القديم حتى عند رجوع الكمية إلى قيمتها السابقة (ABA). واجهة قديمة بلا نسخة تتلقى428 وتحتاج التحديث، بدل كتابة عمياء. الترحيل0041 لا يعيد كتابة الكميات.
- القراءة بلا تكلفة؛ صلاحية `inventory.stocktake.count` تمنح عدّ جرد قائم داخل الشركة والفرع والمستودعات المحددة فقط. لا إنشاء أو إقفال أو اعتماد فروق أو تكلفة ضمنية. تجدد الأهلية داخل معاملة العد خلف حاجز تغيير الصلاحيات.
- المسار المبسط يرفض عد المتغيرات أو الدفعات المبهمة بدل دمجها في المنتج الأساس؛ ليس دليل اكتمال واجهة عد الدفعات والمتغيرات.
- ملاحظة العد ونسختها وتدقيقها داخل المعاملة القائمة؛ لا محرك مخزون أو محاسبة موازٍ.

## حدود ثابتة
سلامة العد لا تثبت سلامة تطبيق الفرق المالي. لم يغير هذا العمل محرك الإقفال القديم، ولم يمنح الإقفال للمستخدم المقيد. حركة بعد لقطة الجرد وتداخل جلسات المستودع تحتاج سياسة قطع/مصالحة مستقلة قبل توسيع اعتماد الفروق.
المحاولات محفوظة في متصفح/جهاز واحد وليست بيعًا Offline أو مزامنة والجهاز مطفأ. لا مسح تلقائي لها بالخروج. فقد/مسح تخزين المتصفح يحتاج مصالحة بسجل الخادم، ولا يمكن ضمان الاستعادة بعد حذف المستخدم لتخزينه.

## دليل التحقق
تسجل نتيجة المصدر النهائي ومرور المتصفح هنا بعد التنفيذ، ولا تحسب الاختبارات السابقة نجاحًا للنسخة الجديدة. الفحص المركز المرحلي:41API و152UI نجحت قبل إضافة حالات التزامن النهائية؛ ليست أرقام تسليم النسخة النهائية.
