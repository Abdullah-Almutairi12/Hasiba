# أساس أسعار أوامر البيع والتحويل — سجل الشريحة

## النطاق والحالة
الشريحة تستخدم الخدمات الأصلية لأوامر البيع والفواتير والمخزون والموافقات
والمعاينة ومحاولات المالية. ليست تفعيلًا عامًا للسياسة الضريبية أو قبولًا حيًا
من زاتكا. تقرير النتائج النهائي الثنائي اللغة وحزمة الأدلة يسلّمان مع نسخة المصدر.

## الضوابط البرمجية
- تحفظ العملة SAR، وشمول السعر للضريبة، والكميات والأسعار والخصومات ومصدر السعر.
- لا يعاد التسعير من بطاقة الصنف أو افتراض السعر الحالي عند التحويل.
- خصم الاتفاق له موازنة كمية تراكمية دقيقة؛ الباقي يستوعب فرق تخصيص الهللات.
  الضريبة تحسب لكل فاتورة فعلية بمحرك التجميع الأصلي، ولا يجمد تقدير ضريبة الأمر.
- معاينة الخادم وتأكيدها مرتبطان بمصدر الأمر والكميات وسياسة الضريبة.
  يظهر الفرق النهائي عن تقدير الأمر عند استنفاد الكميات.
- انتظار الأقفال لا يعفي من فحص عضوية المنفذ ونطاق الفرع وأهلية المعتمد الأصلي.
  استرجاع الإيصال وإغلاق المحاولة يخضعان للنطاق الحالي كذلك.
- لا يكرر إصدار الفاتورة حركة تسليم سبق تسجيلها. يستخدم دفتر تكلفة الأصل القائم.
- الأمر القديم بلا دليل أساس السعر محجوب حتى مراجعة صريحة مع إثبات هوية وسبب
  وسجل تدقيق؛ لا يحدث ملء آلي ولا تغيير للمجاميع التاريخية.

## الحدود المحددة
1. تحويل SAR فقط؛ لا يفترض سعر صرف لقائمة أسعار بعملة أخرى.
2. الأوامر القديمة المفوترة جزئيًا بلا أساس سعر تحتاج مصالحة تاريخية مدققة،
   وليست مؤهلة لعملية الإثبات البسيطة.
3. خصومات قواعد قديمة بلا توزيع محفوظ على البنود محجوبة؛ لا تنقل تلقائيًا
   إلى حساب الخصم اليدوي. الأوامر الجديدة تحفظ دليل التوزيع.
4. تسليمات ذات معاملات ضريبية مختلفة محجوبة إلى حين تخصيص البنود إلى
   دليل الاستحقاق المناسب؛ لا تستخدم أول تاريخ لتخمين معالجة بقية التسليمات.
5. تاريخ المستند المؤكد دليل معلن في النظام وليس شهادة على وقت التسليم الفيزيائي.
   الدفعات المقدمة والعقود المستمرة والاستثناءات التعاقدية/الحكومية ليست قبولًا مثبتًا
   لهذا المسار العادي للسلع المسلّمة.
6. لا تفعيل ضريبي عام، ولا ربط أو إرسال إنتاجي للهيئة، ولا ادعاء دعم الدول الأخرى.

## المراجع
إرشادات الهيئة: تاريخ الاستحقاق عادة أسبق التوريد أو إصدار الفاتورة أو استلام
المقابل؛ توجد حالات خاصة. حفظ سعر الاتفاق ليس حفظ المعاملة الضريبية إلى الأبد.
المقتطفات والروابط وتاريخ المراجعة ضمن `official-tax-references.json` بحزمة الأدلة.

## نقطة الاستئناف
لا يبدأ نطاق آخر تلقائيًا. نتائج القبول والفشل وحدود تجربة المتصفح والمصدر
المختبر والمزامنة تحددها حزمة التسليم النهائية، لا أرقام الشرائح التاريخية.

## الرحلة والمصالحة المستقلة
استُخدمت PostgreSQL منفصلة وبيانات مصطنعة، دون بيع أو تحصيل خارجي.
أنشأت الواجهة الأصلية أمرًا لثلاث وحدات بسعر 115 ريالًا شامل الضريبة، ثم سلّمت
الثلاث. صدرت فاتورة لوحدة واحدة، وحُجب ردها بعد إثبات إيصال الحفظ الفعلي،
ثم أعادت الصفحة تحميل المحاولة نفسها بكمية واحدة مقفلة وبالبائع المحفوظ.
استُعيدت الفاتورة الأولى نفسها، ثم صدرت فاتورة الوحدتين المتبقيتين.

| البيان | نتيجة SQL المستقلة |
| --- | --- |
| الفاتورتان | 115 + 230 = 345 ريالًا |
| ضريبة المخرجات | 15 + 30 = 45 ريالًا |
| الكميات المسلّمة / المفوترة | 3 / 3 |
| المتبقي الفعلي وطبقات FIFO | 17 وحدة بتكلفة 50 |
| قيمة المخزون والأستاذ | 850 ريالًا |
| تكلفة المبيعات | 150 ريالًا |
| الذمم المدينة / صافي الإيراد | 345 / 300 ريال |
| إيصالات محاولة الفوترة | إيصالان، مع ثلاث طلبات: حفظ وفقد رد، استرجاع، فاتورة الباقي |

الحواجز الحقيقية في PostgreSQL اختبرت سباق التنفيذ والإغلاق بترتيبي البداية.
تتضمن السجلات انتظار الأقفال والنتيجة المحفوظة، وليس تأخير JavaScript وحده.

## الإخفاقات المكتشفة وإصلاحها
1. احتاج تحويل الأمر ذي السياسة الجديدة إلى مسار معاينة مؤكد بدل الحجب العام
   السابق؛ أعيد استخدام الحسابات والموافقات والتكلفة القائمة.
2. تاريخ افتراضي UTC لم يطابق يوم الرياض عند منتصف الليل؛ وُحّد افتراض
   تاريخ الأمر والتسليم مع اليوم المحلي للسياسة.
3. ظهرت لوحة استرجاع دون محاولة؛ أصبحت مشروطة بوجود محاولة، وتعرض الكمية
   المحفوظة بعد إعادة التحميل بدل الكمية المتبقية الجديدة.
4. المحاولة الأولى للمتصفح لم تحجب الرد بسبب قراءة موضع غير صحيح لهوية
   الفاتورة في إيصال الاختبار. ليست دليل قبول لفقد الرد. أُصلحت أداة الاختبار
   وأعيدت الرحلة بنجاح؛ حُفظت أدلة المحاولة الأولى أيضًا.
5. أثبت اختبار قبل الإصلاح قبول مراجعة أساس قديم خارج نطاق الفرع رغم صحة
   إثبات الهوية؛ أضيف فحص النطاق داخل المعاملة، وأصبح الاختبار يثبت الرفض.
6. أثبت اختبار قبل الإصلاح أن بقاء الإجمالي الشامل ثابتًا لم يكن يبطل اعتمادًا
   تغيّر صافي قيمته وضريبته. أصبحت المقارنة تشمل الصافي والخصم والضريبة
   والإجمالي بدقة الهللة، لا الإجمالي وحده.
7. صُححت تجهيزات اختبارات كانت تفترض طبقات FIFO مع منتج متوسط التكلفة،
   وتفتقد حقول مسؤولية إلزامية. جرى ذلك على البيانات المصطنعة فقط، دون تعديل
   سياسة تكلفة منشأة قائمة أو إضعاف تحقق مالي.
8. أُضيف الترحيل الجديد إلى قائمة الترقية المتوقعة مع الإبقاء على اختبارات
   العلاقات والبيانات التاريخية؛ لم تُحذف اختبارات الانحدار.
9. تعذّر إنشاء المتصفح مرة بخطأ خارجي Browserbase/OpenInt HTTP 503، دون دخول
   أو طلبات ERP؛ نجحت إعادة واحدة محدودة للرحلة النهائية. لا يُحسب تعذر بدء
   المتصفح اختبارًا ناجحًا أو فشلًا برمجيًا في التطبيق.
10. تعطل تجميع الأدلة أولًا لافتراض وجود ملف stdout مستقل لبوابة ثبات المصدر؛
    هي مقارنة داخلية مثبتة في JSON النهائي، فحُفظ سجلها الفعلي بدل اختلاق ملف
    تشغيل. لم يتغير المصدر المختبر أو نتيجة أي بوابة بسبب إصلاح التجميع.

## الترحيل والتشغيل المحلي
الترحيل `0070_sales_order_pricing_basis.sql` إضافي وnullable؛ لم يملأ أساس أسعار
الأوامر القديمة تلقائيًا. نجح التركيب المستقل والترقية التاريخية. عند استعادة
خدمة API التطويرية طبّق مسارها المعتاد الترحيل الإضافي، دون تغيير بيانات
المستندات السابقة. لم تُشغّل اختبارات كتابة على بياناتها؛ جميع الرحلات والاختبارات
المالية شُغلت على قواعد PostgreSQL منفصلة. لا ترحيل أو نشر إنتاجي.

## ما بقي غير مثبت أو محجوب
- لا قبول عام للمرحلة الضريبية أو إنتاج زاتكا؛ يبقى `TAX_POLICY_NOT_READY`.
- لا تحويل متعدد العملات أو تفسير تلقائي لأساس قديم مجهول، أو إعادة تفسير
  أوامر قديمة مفوترة جزئيًا أو خصومات قديمة بلا توزيع.
- لا تخصيص آلي لتسليمات تمت بمعالجات ضريبية مختلفة، ولا قبول مثبت للدفعات
  المقدمة والعقود المستمرة والحالات الحكومية الخاصة.
- إذا تغيرت حقائق اعتماد سابق تُحجب الفوترة إلى حين مراجعة موثقة؛ لا تنشئ هذه
  الشريحة استثناءً ولا تعتبر تأكيد معاينة المستخدم اعتمادًا بديلًا.
- لم تختبر طباعة ورقية أو أجهزة دفع أو قبولًا حيًا أو تنزيل PDF لهذه الشريحة.
  تحذير وصف الحوار في المتصفح غير مانع ومبيّن في تقرير الاختبار؛ لم يُخفَ.
- لا تغلق هذه الشريحة بقية مرحلة الضرائب أو صلاحيات ERP أو المتبقي الأصلي.

ملف التسليم النهائي وحزمة الأدلة يبينان حالة Push الفعلية وآخر Commit المرفوع.
المخرجات المولّدة مستثناة من Git؛ تسلّم كملفات فعلية، لا باعتبارها موجودة في المستودع.
