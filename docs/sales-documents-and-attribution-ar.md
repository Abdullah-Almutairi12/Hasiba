# حاسبة.AI — مستندات البيع وإسناد البائع

## النطاق وحدود الحكم

هذه الدفعة داخل مشروع ERP الحالي وعلى فرع المزامنة القائم، وليست مشروعًا أو مستودعًا بديلًا. تنفذ هوية الشركة ومطبوعات التشغيل أولًا، ثم إسناد البائع وتقاريره والعمولات. لا تعلن اكتمال ERP أو إغلاق جميع متطلباته أو خلوه من جميع الثغرات.

سجل النطاق الأصلي هو `enterprise-requirements-ar.md`: احتفظ بمعرفاته الثلاثة والسبعين وترتيبه، ولا تنشأ مهام جديدة بدل المتطلبات القائمة. حدّث البندان 08.4 و08.5 جزئيًا؛ ربط الأهداف والرواتب والتكاملات الفعلية ليس منجزًا.

## التقنية القائمة

- واجهة React وTypeScript وVite، ضمن مساحة pnpm مشتركة، بمكونات عربية وRTL وReact Query.
- API قائم على Express وTypeScript، مع PostgreSQL وDrizzle وترحيلات مرتبة وعزل الشركات وصلاحيات الفروع.
- عقد OpenAPI وتوليد العميل والمخططات باستخدام Orval؛ أضيفت مسارات منفصلة للطباعة وإسناد الموظفين.
- محرك PDF القائم: Chromium والخط العربي المرفق. لم يستبدل المحرك ولم يعد بناء دورة المحاسبة أو المخزون أو المرتجعات.
- التخزين القائم للملفات مستخدم للشعار؛ تحفظ قاعدة البيانات مفتاح الملف وبصمته وملكيته، لا صورة Base64.
- وظائف الذكاء الاصطناعي والوحدات الأخرى ليست موضع اختبار جودة في هذه الدفعة؛ لا توجد نسبة تعلم أو جاهزية مقاسة ضمن هذا التقرير.

## المرحلة الأولى: الهوية والمطبوعات

### ما تغير

- هوية الطباعة تخص الشركة الحالية: الاسم القانوني بالعربية والإنجليزية، التسجيل الضريبي والسجل التجاري والعنوان المنظم ووسائل الاتصال والبنك والشروط والشعار وعروض الإيصال.
- لا يستنتج المصدر بيانات شركة من إعدادات عامة أو متغيرات بيئة أو شركة أخرى.
- الحفظ لأصحاب الصلاحية، مع رقم نسخة وتعارض تحديث واضح وسجل تغييرات. بقية المستخدمين يقرؤون ما يسمح به نطاقهم.
- الشعار يمر بمسار مخصص للشركة وفحص نوع وحجم وبصمة، وتحفظ نسخه القديمة لخدمة المستندات التي تشير إليها.
- تحفظ هوية الإصدار مع المستند الجديد داخل معاملته، فلا تتغير هوية الفاتورة القديمة عند تعديل ملف الشركة.
- لا تولد رموز QR للمستندات القديمة ولا تعاد كتابة المستندات الموقعة أو المرسلة. القديم بلا نسخة هوية يظهر نقصه صراحة.
- فحص QR للقراءة يقارن القيم المحفوظة بهوية الإصدار والإجمالي والضريبة؛ ليس اعتمادًا رسميًا من زاتكا ولا إثباتًا للتوقيع أو الإرسال أو القبول.
- الفاتورة القديمة ذات الهوية المفقودة تحتفظ بأرقام الضريبة والرمز المخزنين؛ لا تعامل باعتبارها منشأة غير مسجلة ولا تخفى أرقامها المعروفة.
- تنزيل الفاتورة ومرفق إرسالها يستخدمان مسار العرض نفسه؛ لم ينفذ إرسال بريد أثناء الاختبار.

### المطبوعات الفعلية

- فاتورة عميل A4 وهوية وQR محفوظان عند توفرهما.
- إيصال بيع 80 أو 58 مم من طلب مؤكد، مع طرق التحصيل والمدفوع والمتبقي والإجمالي والمحصل والبائع المحفوظ عندما كان إسناده ظاهرًا.
- إشعار دائن مرتبط بالفاتورة الأصلية وبنودها.
- سند استرداد نقدي مؤكد؛ وطلب إلكتروني غير منفذ؛ وتأكيد يدوي مبني على إثبات خارجي، مع تمييز واضح بينها.
- محضر إقفال محفوظ: افتتاحي ومقبوض ومصروف واستردادات ومتوقع ومعدود وفرق وحالة الاعتماد.
- تقرير VAT القائم يعرض التصنيفات المتاحة؛ التوريدات المعفاة غير المثبتة تعرض «غير متاح» لا صفرًا مختلقًا.
- أصلحت صفحة معاينة فاتورة المورد لتطلب PDF المورد الصحيح بدل خلط معرفه بمعرف فاتورة العميل.
- إعادة الطباعة قراءة فقط، ولا تنشئ بيعًا أو فاتورة أو حركة مخزون أو قيدًا جديدًا. الروابط المباشرة تخضع للشركة والفرع.

## المرحلة الثانية: البائع والعمولات

- الموظف هو مصدر البائع، وقد لا يملك حساب دخول. المحصل ومستخدم إنشاء الفاتورة لا يصبحان بائعًا تلقائيًا.
- السياسة مخفي/اختياري/إلزامي، وللفاتورة أو السطر، مع افتراضي الشركة ووراثة الفرع أو تخصيصه، وموعد سريان ونسخة محفوظة.
- الأهلية صريحة للموظف والفروع؛ لا يكفي إدخال معرف موظف من شركة أو فرع آخر.
- طبقت السياسة في نقطة البيع والفاتورة اليدوية. الفرع المحدود لا يتجاوز سياسته بإرسال فاتورة بلا فرع.
- تحفظ اختيارات البائع ضمن جسم محاولة الدفع وبصمتها. أثناء النتيجة المجهولة تقفل الاختيارات وتستعاد المحاولة نفسها، لا عملية جديدة.
- الاسم المعروض للبيع المؤكد والمسترد يأتي من النسخة المحفوظة، لا من قائمة موظفين حالية قد تغيرت.
- التقرير بحسب الفترة والفرع والبائع: إجمالي البيع والخصومات والمرتجعات والإلغاءات والصافي قبل الضريبة، والفواتير الفريدة وغير المنسوب. لا تجمع العملات في إجمالي واحد.
- اعتماد فواتير العميل مصدرًا موحدًا يمنع عد بيع POS وفاتورته المرحلية مرتين. الفاتورة متعددة البائعين تظهر في صفوفهم لكن تحسب مرة واحدة في الإجمالي الفريد.
- العمولة معطلة افتراضيًا. تفعيلها يتطلب نسبة صريحة أو خطة بسيطة مملوكة للشركة. لم تفترض نسبة عمل تجارية؛ أي نسبة في الاختبار تخص شركة تجريبية فقط.
- تستخدم خطط العمولات الموجودة مع ملكية شركة صريحة؛ لا تمنح الخطط العامة القديمة ملكية شركة بالتخمين، ولا تستخدم أول خطة عامة بديلًا تلقائيًا.
- هذه الدفعة تدعم نسبة بسيطة من صافي ما قبل الضريبة وبعد الخصومات والمرتجعات، لا مخططات الحصص والشرائح والمكافآت المركبة.
- تتبع المرتجعات البائع وبند البيع الأصلي وسياسة إصداره، لا كاشير المرتجع أو نسبة اليوم، حتى لو وقع المرتجع لاحقًا.
- توزع الهللات دون فقد، ويجري حساب النسبة بأعداد صحيحة وتقريب متناظر؛ تعالج بواقي المرتجعات بحيث يعكس الرد الكامل العمولة الباقية.
- التصحيح بعد البيع يحتاج إذنًا وسببًا ويسجل قبل/بعد والمنفذ. لا ينشئ فاتورة أو حركة مخزون أو قيدًا محاسبيًا جديدًا.
- المعتمد والمدفوع لا يعاد حساب مبلغيهما أو محوهما بسبب مرتجع أو تصحيح؛ تضاف حركات تسوية قابلة للمراجعة.
- الحالات محسوبة ومعتمدة ومدفوعة منفصلة. «توثيق دفع خارجي» تسجيل إثبات، لا تحويلًا ولا صرف راتب ولا قيدًا جديدًا.
- السجلات القديمة بلا إسناد لا تستكمل من المستخدم الحالي ولا تعاد حساب عمولاتها بإعدادات اليوم. تتوقف شاشة التصحيح لها بدل تخمين نسخة تاريخية.

## التحقق وإعادة الإنتاج

- الاختبارات المالية تعمل عبر `scripts/test-isolated.mjs` على PostgreSQL محلي مؤقت؛ لا تستخدم بيانات العملاء أو قاعدة الإنتاج.
- الاختبارات المستهدفة تغطي شركتين، وصلاحيات الفرع، وتغير الهوية بعد الإصدار، وQR، وإعادة الطباعة، و58/80 مم وA4، وحالات الاسترداد والإقفال.
- اختبارات البائع تغطي الأنماط الثلاثة والوراثة والموظف بلا دخول والتعطيل وإعادة المحاولة وبواقي الهللات وتعدد البائعين والمرتجع الجزئي والكامل والإلغاء وتصحيح نسبة معتمدة أو مدفوعة.
- اختبارات الواجهة تغطي اختيار البائع والفاتورة اليدوية والتحميل الفاشل والنتيجة المجهولة واستعادة الجسم نفسه والسياسة التاريخية للتصحيح والعملة والعدد الفريد.
- أصلح تمييز أخطاء Zod للإصدارين المستخدمين، لتعود المدخلات غير الصالحة 400 بدل 500.
- الفحص الحاسم هو تشغيل `pnpm run verify` على مصادر الدفعة النهائية؛ أرقام المراجعات القديمة ليست دليل نجاح جديد. تحفظ مخرجاته وبصمة مصادره ضمن `generated-artifacts/verification/`.
- تجربة المتصفح المخصصة تستخدم شركة وحسابات ومنتجات وموظفين تجريبيين فقط، وعلى الهاتف واللوحي والكمبيوتر، مع فقد رد بعد إثبات الالتزام ثم الاستعادة.
- المرفقات النهائية تعرض نتائج التشغيل الفعلية وبصمتها وحدود تجربة المتصفح؛ أي مانع أو قصور يبقى معلنًا ولا يستبدل بنسبة إنجاز تخمينية.

## ما لم يختبر أو لم ينفذ

- طابعة فعلية أو درج نقدي أو شاشة عميل أو أجهزة USB/Bluetooth أو شبكة دفع أو تحويل بنكي حقيقي.
- اعتماد إنتاجي للمرحلة الثانية من زاتكا، أو إرسال XML موقّع أو شهادة أو استجابة قبول فعلية.
- رفع شعار إلى التخزين الخارجي أثناء الاختبارات؛ جهز المسار وصلاحياته، ولم ينفذ رفعًا خارجيًا بلا موافقة.
- صرف عمولات ورواتب فعلي أو مزامنتها المحاسبية الآلية، أو ربط أهداف الموظفين، أو عمولات الشرائح والحصص المركبة.
- استعادة معلومات تاريخية مفقودة أو تواريخ إلغاء غير محفوظة. يعرض التقرير التحذير بدل اختراع دليل.
- بقي بلاغ الدفع الأصلي غير مغلق على إطلاقه؛ أثبتت الرحلات المعزولة المحددة، لا اتصال شبكة دفع حقيقية.
- بقيت التجزئة بالباركود والمطاعم ذات الفئات المتفرعة وتوسعات المحاسبة والموارد البشرية وCRM والذكاء الاصطناعي في سجلها دون بدء هذه الدفعة.

## التشغيل والترحيل والتراجع

الترحيلان `0027_document_print_identity.sql` و`0028_seller_attribution.sql` إضافيان: لا يعيدان ملء المستندات القديمة، ولا يغيران القيود أو المخزون أو العملات أو مبالغ الفواتير. عمود ملكية خطط العمولات القديمة يظل غير معين إن لم يوجد دليل.

قبل الإنتاج: خذ نسخة احتياطية مأمونة، وجرب مسار الترحيلات القائم واختبارات هذه الدفعة على نسخة منفصلة، وراجع صلاحيات الشركات والفروع وبياناتها القانونية. لم ينفذ نشر أو ترحيل إنتاجي أو إرسال خارجي في هذه الدفعة.

نقطة الرجوع الكودية المحلية هي `before-document-identity-seller-20261023` على بداية العمل. التراجع الكودي لا يعكس العمليات المالية ولا يبيح حذف جداول اللقطات والعمولات أو ملفات شعارات قديمة. أوقف الكتابة أثناء قرار التراجع، واحفظ الأدلة والنسخ الاحتياطية، ولا تعد تشغيل كود قديم لإصدار مستندات جديدة قبل حماية مساره.

التغييرات على الفرع الحالي `sync/hasiba-erp-20261023`؛ لم يستبدل main ولم يؤرشف الموقع التعريفي ولم ينشأ مستودع جديد. حفظ محلي ليس مزامنة GitHub؛ يصرح التسليم بشكل منفصل بما رفع وما لم يرفع، وبأن المخرجات المولدة المستثناة من Git تسلم كمرفقات.
