# تشخيص عكس القيود — قراءة فقط

تُراجع الأداة التاريخ المالي ولا تُصلحه. لا تحذف أو تعدّل قيودًا، ولا تنشئ قيود تسوية أو سجلات تدقيق. لا تُشغّل ضمن بدء التطبيق أو الترحيلات.

## التشغيل

1. اختر قاعدة البيانات صراحةً عبر السر `JOURNAL_AUDIT_DATABASE_URL`، ويفضّل حسابًا بصلاحية `SELECT` فقط على `public.journal_entries` و`public.journal_entry_lines`.
2. لا تُوجّه الأداة إلى الإنتاج إلا بطلب صريح من المستخدم. لا تستخدم تلقائيًا `DATABASE_URL` ولا تنسخ قيم الاتصال إلى الأوامر أو التقارير.
3. نفّذ:

```sh
pnpm --filter @workspace/scripts run audit-journal-reversals --read-only
```

للمساعدة دون اتصال: أضف `--help` بدل `--read-only`.

المخرجات JSON على stdout؛ عند حفظ تقرير يُفضّل استدعاء `pnpm --filter @workspace/scripts exec tsx src/audit-journal-reversals.ts --read-only` مباشرةً لتجنّب ترويسة `pnpm run`. احفظ التقارير خارج Git وتعامل معها كبيانات مالية حساسة.

رموز الخروج: `0` لا مخالفات، `2` وُجدت مخالفات، `1` فشل الفحص أو المدخلات. الفشل ليس تقريرًا سليمًا أو خاليًا من المخالفات. تُخفى تفاصيل أخطاء الاتصال لمنع تسريب أسرار الاتصال.

## تفسير التقرير

- كل مجموعة تحمل `reversal_of` و`company_id` الأصل ومعرّفاته، وجميع المقابلات مع شركاتها وحالتها وبيانات العكس ومجاميع مبالغها بالعملة الأساسية.
- يكشف تعدد المقابلات بغض النظر عن حالتها، وعدم اتساق `reversed_at`/`reversed_by` مع المقابل، واختلاف `reversed_by` عن `posted_by` للمقابل المنفرد. غياب المستخدم من الطرفين مع وجود التوقيت صالح للعكس الآلي. لا يقارن التوقيتين بالمساواة لأن إنشاء المقابل وتحديث الأصل يتمان في لحظتين مختلفتين.
- يكشف روابط العكس بين الشركات، والأصل المفقود، والأصل أو المقابل غير المرحّل، والعكس الذاتي أيضًا.
- `gl_posted_net_by_company_account` يجمع الأصل ومقابلاته المباشرة **بحالة posted فقط**، لكل شركة وحساب بشكل منفصل: موجب `net_base_debit` يعني صافي مدين، وسالب يعني صافي دائن.
- يحتفظ التقرير بالمبالغ كنصوص عشرية دقيقة. لا تُجمع الشركات، ولا يُستخدم صافي المدين والدائن الإجمالي للقيد المتوازن كدليل على عدم تأثر GL. لكل حساب أثر مستقل.
- المجاميع وصف للأرصدة الفعلية لهذه المجموعة، **وليست قيمة إصلاح مقترحة** أو إثباتًا لوجود مبالغة محددة. تحتاج مراجعة التواريخ والحسابات وسلاسل العكس والسندات. لا تجمع المجموعات المتداخلة في سلسلة عكس لأن القيد قد يظهر في أكثر من مجموعة. الصفر لا ينفي خلل البيانات.
- `company_id: null` مع `MISSING_ORIGINAL` يعني غياب الأصل؛ شركة كل مقابل موجودة داخله وفي مجاميع GL.

## ضمانات السلامة والحدود

اتصال CLI يفرض `default_transaction_read_only=on`، والفحص نفسه يبدأ معاملة PostgreSQL `REPEATABLE READ READ ONLY` بلقطة متسقة ثم `ROLLBACK`. الاستعلامات ثابتة بلا مدخلات SQL، مع مهلة تنفيذ 60 ثانية وانتظار قفل 5 ثوانٍ. لا تصحيح آلي ولا أقفال صفوف للتحديث. الفحص شامل للشركات عمدًا كي لا تختفي روابط عكس عابرة للشركات؛ الأداة إدارية وليست مسارًا متاحًا للمستخدمين.

لا يفحص التقرير جميع أوجه صحة القيود (مثل مطابقة سطور العكس لكل سطر أصلي أو اتساق ملكية الحسابات). إنه تشخيص لروابط العكس وبياناتها وأثر القيود المرتبطة المرحّلة، وليس تدقيقًا ماليًا شاملاً.

## إثبات مستقل على PostgreSQL مؤقت

```sh
pnpm --filter @workspace/scripts run test:journal-reversal-audit
```

يُنشئ المشغّل عنقود PostgreSQL محليًا جديدًا ومخطط المشروع الحقيقي عبر Drizzle، ويزرع بيانات صناعية سليمة ومتعارضة ثم يشغّل **اختبارات هذه الأداة فقط**. لا يقرأ قاعدة التطبيق أو الإنتاج. يثبت اكتشاف المخالفات، وغياب الإيجابيات الكاذبة للعكس الصحيح والآلي وسلاسل العكس، ودقة الأرقام، ومنع الكتابة من PostgreSQL، وتطابق محتويات كل الجداول العامة ومواضع التسلسلات قبل الفحص وبعده. يُغلق العنقود ويحذفه عند الخروج. يتطلب أدوات PostgreSQL في PATH أو ضبط `PG_BIN`.
