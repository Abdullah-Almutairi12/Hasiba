---
name: Stocktake approval independence
description: User-chosen session-wide exclusion of every historical count writer
---
By default anyone who recorded or modified any counted quantity is disqualified
from approving the entire stocktake session, including managers. Retain participation
after count deletion, recount and task reassignment. A checkpoint alone, viewing
or merely creating the session does not establish count participation.

**Why:** The user explicitly chose this policy on 2026-10-26, resolving the
previously unanswered segregation decision. Do not extend a generic document
creator prohibition to stocktakes just because a creator field exists.

**How to apply:** Require an otherwise authorized independent reviewer and keep
existing request self-approval controls. Recheck under the native parent and
stock execution locks. If nobody qualifies, leave the session pending without
posting and explain why. Audit count participants and the acting reviewer.
Never infer historical actors from assignments or erase them with count rows.
Missing historical identity cannot be cured merely by recounting: that would
silently erase the unknown previous participant. Preserve the evidence gap.

The user later explicitly authorized a company-policy exception for combined
responsibilities. It must be OFF for existing companies and require a distinct
explicit permission, finite monetary bound, recorded reason, current identity
proof, and an audited policy change. Role names/ownership never suffice.
Recheck the original reviewer's eligibility at posting, not just the poster's.
Unknown historical count identity is NEVER exemptible.

**Why:** The same 2026-10-26 scope clarification requires operating a single-person
establishment without weakening the default or silently treating a missing
historical identity as known.

**How to apply:** Keep counting, review and posting permissions separate; a native
review is evidence, not a financial write. Use the native stock/GL transaction and
durable closure receipt. Preserve original audit history when resolving a legacy
session; a new evidenced count is a new session, not retroactive proof of the old one.
